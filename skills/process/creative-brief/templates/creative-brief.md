# CREATIVE_BRIEF.md structure

Read this at create step 6 and at the end of review mode.

Write in English. Save the file in the project's established documentation directory when one exists,
and the project root otherwise. Update the same file; never create dated copies.

The metadata does not count as a content section. Keep the four headings exactly as written.

```markdown
# Creative Brief: <project or design round>

**Status:** `draft | awaiting-research | review-needed | ready`
**Version:** `v1`
**Last reviewed:** `YYYY-MM-DD`
**Evidence companion:** `CREATIVE_BRIEF_EVIDENCE.md`

## Project Objective

Two or three sentences describing what this part of the project will accomplish relative to the
larger effort.

## Key Personas

### <Persona name>
One or two sentences containing only the researched characteristics that affect this design round.

### <Optional second persona>
One or two sentences. Omit the heading when there is only one.

## Key Scenarios

1. **<Scenario name>.** Two or three sentences naming the trigger, goal, and context the design must
   support.
2. **<Optional second scenario>.** ...
3. **<Optional third scenario>.** ...

## Key Principles

1. **<Trade-off in memorable form>.** One sentence explaining which side should win when the values
   conflict.
2. **<Optional second principle>.** ...
```

## Hard caps

- One Project Objective, two or three sentences.
- One or two Key Personas.
- One to three Key Scenarios.
- One or two Key Principles.
- No fifth content section.

If the brief cannot fit these caps, selection is unresolved. Move context to the evidence companion;
do not compress several personas or scenarios into one disguised list item.
